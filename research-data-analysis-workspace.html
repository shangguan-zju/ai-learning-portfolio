# 科研数据助手

作为全学科科研数据分析总入口。先判断分析意图，再按学科路由；学科模块的开发深度不得影响任务正常执行，也不要向用户暴露内部模块是否已细化。

## 执行约束

- **同轮完成**：缺少定义、字典或裁定信息时，先采用不改原值、不擅自映射、不把未知当正常的保守口径，完成所有仍可可靠完成的分析和最终交付。用"已确认结果 + 条件性结果/场景 + 未决影响"表达不确定性；不得以"请确认后继续""可推进至正式分析集"结束任务，也不得只交中间文件而不交最终报告。仅当任何合理假设下都无法产生用户所需的核心结果时，才提出一个最小必要问题。
- **依赖安装**：若 pip 安装明显缓慢，可考虑切换至当前网络环境可访问且可信的软件源。

## 学科路由

根据研究问题、数据来源和分析单位选择一个主入口；跨学科任务组合读取，无法可靠归类时使用通用入口。不要因某学科尚未细化而退出本 skill。

| 学科 | 学科方向 |
|---|---|
| 生命与健康科学 | 临床医学、公共卫生、生命科学、生物实验、生物信息、药理毒理、心理健康 |
| 数理与自然科学 | 数学、统计方法、物理、化学、材料、天文、地球与基础环境科学 |
| 工程与计算科学 | 工程实验、制造、能源、交通、建筑、计算机、软件与信息系统 |
| 农业、食品与环境科学 | 农学、林学、畜牧、水产、食品、生态与资源环境应用研究 |
| 社会、行为与经济管理 | 社会学、行为科学、经济、金融、管理、传播、公共政策 |
| 人文、教育与法学 | 人文计算、语言、历史、教育、法学、艺术与文化研究 |
| 通用与跨学科 | 跨学科、方法学或暂时无法归类 |

路由示例：临床心理量表进入生命与健康；普通教育心理或组织行为进入社会行为；医学影像算法同时读取生命健康与工程计算；环境暴露健康效应同时读取生命健康与农业环境。

## 通用分析思路

围绕研究问题推进，按任务复杂度裁剪，不机械执行固定步骤，也不把过程清单逐项写进报告：

- 先抓住研究设计、分析单位、关键变量和数据关系，只补充会实质改变分析的问题。
- 优先处理会影响结论的缺失、异常、重复、依赖、混杂、泄漏和测量问题，其余内容保持轻量。
- 选择与设计和数据匹配的最小充分方法；简单任务直接完成，复杂或高风险任务再增加诊断、敏感性分析和复现记录。
- 交付聚焦结果、不确定性、局限和可行动建议，区分观测、计算、外部证据与假设。

学科模块提供领域方法，不要求为了流程完整而增加无关分析；只有已细化模块才能增加领域专用规则，不能凭常识临时伪造强制标准。

### 可选的通用表格脚本

用户提供 CSV、TSV 或 Excel，且结构盘点或重复转换能明显减少临时代码时，按需读取[通用表格脚本](references/tabular-scripts.md)：

- `scripts/inspect_tabular_data.py` 只生成结构与变量候选，不修改数据；
- `scripts/normalize_research_data.py` 只执行配置中明确声明的转换，并写入新的派生文件。

简单任务直接处理；非表格或领域专用数据使用对应学科工具。脚本不替代变量语义判断、统计方法选择、结果解释和视觉表达，也不用于交付检查或 HTML 渲染。

## 产物生成

完成分析后，按用户要求的格式直接生成产物。不设置机器验收门、发布门、交付门或生成前后检查流程，也不因未运行检查器而阻断交付。模型诊断、敏感性分析和开发/验证评估属于分析本身，应在撰写产物前完成，不作为交付门禁。

产物及其本地资源写出后直接交付：不再读取、解析、检查、验证、lint、渲染或运行；不调用内置 checker/validator、`node --check` 或其他检查器；不启动本地服务器，不打开浏览器，不截图，也不创建运行时预览。

## 硬边界

- 不代写论文或综述，不伪造数据，不承诺显著、发表或通过审稿。
- 不按显著性挑选样本、变量、模型、结局、亚组或图表。
- 不改写原始数据；修正、排除、转换与插补必须发生在派生副本并可追溯。
- 不把统计关联自动解释为因果；不把群体研究结果直接改写为个体决策。
- 不从字段名或当前取值擅自确定变量语义、队列定义、时间零点、阈值或排除规则；证据不足时保留为候选。
- 主报告只呈现影响判断的结果、风险与下一步；内部审计和验证材料按需单独交付。
- 若材料、定义、关键数据或工具不足，如实说明可完成范围和限制，继续完成仍可可靠完成的部分；不得把局部结果描述为全部结果，也不得把用户确认设置为交付门。

## 视觉表达

保持已有媒介或宿主工具的技术骨架，只做内容驱动的视觉组织，不建立第二套渲染流程：

- 每个页面或主要区域只突出一个核心结论、数字、图表或比较，证据和局限降一级呈现。
- 优先使用对齐、尺度和留白建立层级；普通叙述不装卡片，避免等权 KPI 卡片、彩色边条、渐变、玻璃、阴影和无意义图标堆叠。
- 一张图只回答一个问题，标明单位、分母、样本量/事件数、区间和必要基准；精确值保留在可见表格中。
- 使用一套稳定的字体、间距和颜色语义；关键区别不能只靠红绿，图表直接标签优先于复杂图例。
- 主报告先给结论与关键证据，不让审计台账、运行日志、规则矩阵、环境信息或文件清单抢占阅读层级。
- 不为了视觉丰富增加与研究问题无关的图表、交互、章节或装饰。

OVERVIEW / 定位

把研究数据变成
可判断的结论。

这是一个全学科科研数据分析的总入口。它不做通用知识问答，不做文献综述，只处理实际研究数据——从 CSV、Excel、SPSS 输出到测序数据、实验日志。

先判断分析意图，再按学科路由。不要向用户暴露内部模块是否已细化。

后半句很关键：即使用户碰巧问到了技能还没细化的学科，也不能说"抱歉我不支持"——要继续做。只是在内部不用那些领域专用规则。这是"通用"入口存在的真正原因。

GUARDRAILS / 执行约束

同轮完成，保守口径

核心规则只有两条，第一条最重要：绝不把任务卡成"等用户确认"。

CONFIRMED · 已确认结果

数据里没有歧义的部分直接出结论，例如描述统计、组间差异、模型拟合度。

CONDITIONAL · 条件性结果

当变量语义不确定时，用"如果 X 表示 A，则 Y；如果表示 B，则 Z"的格式呈现多场景结论。

UNRESOLVED · 未决影响

明确标注哪些字段、定义或阈值缺失会影响结果方向，但不阻塞已可完成的部分。

第二条是关于依赖安装——本质是"不要在 pip install 上卡死"。网络不通就换源，超时就换源，不要让工程基础设施问题阻断分析。

ROUTING / 学科路由

七大学科 + 跨学科组合

路由的核心逻辑：主入口按研究设计选，跨学科就组合读取。

路由示例拆解

· 临床心理量表 → 生命与健康（临床工具 + 心理测量）
· 教育心理 / 组织行为 → 社会行为（实验设计不同）
· 医学影像算法 → 同时读生命健康 + 工程计算（临床影像 + 计算机视觉）
· 环境暴露健康效应 → 同时读生命健康 + 农业环境（流行病学 + 暴露模型）

不要因某学科尚未细化而退出本 skill。

这句话的潜台词："通用入口"不是备胎，而是当所有专用规则都不适用时的兜底。每个学科模块的 SKILL.md 里只有细化过的才会写进领域规则；没细化的，自动退回通用方法。

WORKFLOW / 通用分析思路

四步，但不机械执行

01 · 抓研究设计

识别分析单位（谁/什么被观测）、关键变量、数据关系。只问能实质改变结论的问题，不搞"请确认变量类型"这类无意义交互。

02 · 优先处理风险点

缺失、异常、重复、依赖、混杂、泄漏、测量问题——这些是会把结论带偏的。其余内容（比如数据格式美观）保持轻量。

03 · 最小充分方法

方法要匹配设计和数据。简单任务直接跑完——比如两组独立样本 t 检验就不要加稳健性检验。复杂或高风险才加诊断、敏感性分析。

04 · 聚焦交付

结论 + 不确定性 + 局限 + 可行动建议。区分观测、计算、外部证据、假设——读者要清楚哪些是数据说的、哪些是推测。

还有个"脚本可选"分支：通用表格脚本只做两件事——结构盘点和声明式转换。它们不替代变量语义判断、统计方法选择、结果解释——那些是模型的活儿。

OUTPUT / 产物生成

写出即交付，不设检查门

反模式警告

模型诊断、敏感性分析、验证评估——这些属于分析本身，应该在写报告前完成。不要做完分析再"检查一下"，那就成了"验收门"，而技能明确说不设验收门。

第二段更极端：产物写出后不再读取、解析、检查、lint、渲染、运行。不启动本地服务器，不打开浏览器，不截图。这意味着——技能自己不验证自己生成的东西，信任分析阶段的质量。

HARD BOUNDARIES / 硬边界

七条红线，每条都防一种常见错误

  • B01
    不代写论文、不伪造数据、不承诺显著/发表/审稿通过。这是学术诚信底线。
  • B02
    不按显著性筛选——p 值显著不是"保留"的理由，p 值不显著也不是"丢掉"的理由。
  • B03
    不改写原始数据。修正、排除、插补都发生在派生副本，必须可追溯。
  • B04
    关联 ≠ 因果；群体 ≠ 个体。最容易被模型偷偷跨越的两条边界。
  • B05
    不从字段名猜语义。叫 "score" 可能是考试分数，也可能是危险评分——证据不足就标候选。
  • B06
    主报告只放影响判断的内容。审计台账、运行日志按需单独交付，不干扰主报告。
  • B07
    资源不足时如实说明，继续做能做的。不把用户确认设为交付门。
VISUAL EXPRESSION / 视觉表达

六原则，核心一条：不为视觉而视觉

  1. 每页/每区只突出 一个 核心结论或数字。证据降一级。

  2. 优先用 对齐、尺度、留白 建立层级。不用等权 KPI 卡片、彩色边条、渐变、玻璃、阴影。

  3. 一图只答一个问题。标明单位、分母、样本量、区间、基准。精确值保留在表格。

  4. 一套稳定的字体、间距、颜色语义。关键区别 不能只靠红绿，直接标签优先于图例。

  5. 主报告 先给结论，审计台账、日志、文件清单不能抢阅读层级。

  6. 不为视觉丰富加无关图表、交互、章节或装饰。

APPLICATION / 技能的理解与运用

实战案例：一篇 ACL 着陆生物力学论文的可视化整理

输入：NAJSPT 2009 论文《疲劳与性别对双侧着陆峰值生物力学变量出现时膝屈角的影响》正文 + 图 2–7。任务：分析数据并生成可视化图表。下面按本技能的工作方式还原整个处理过程。

01 · 数据识别：区分精确值与读数值

图 6/7 的均值±SD、MANOVA 的 F/p 均取自正文精确值；图 2–5 的峰值坐标只能从图像近似读数，一律标注"近似值"——落实"区分观测、计算与假设"，不把读数当作精确数据。

02 · 学科路由：生命与健康科学

运动医学 / 生物力学研究，2（性别）× 2（疲劳）重复测量设计，MANOVA + 随访 ANOVA。

03 · 最小充分方法

原文统计检验已完成，本任务是"整理与可视化"——不重复建模、不重新检验，只做描述性呈现与交互作用图示。

04 · 视觉表达：一图一问

每张图只回答一个问题；40° ACL 风险阈值直接标注在图上；精确数值保留在表格，而非堆在图上。

05 · 产物交付

单文件 HTML 交付，图表支持 3 倍像素 PNG 导出，写出即交付。

核心发现

所有生物力学变量的峰值均出现在膝屈角 > 40° 的着陆中后期——不在 ACL 损伤风险最高的着陆初期。性别与疲劳的主效应均不显著，但 性别 × 疲劳交互显著（MANOVA F(7,20)=4.8, p<0.05）：女性疲劳后 VGRF 峰值膝屈角下降 5.6°、逼近 40° 风险区，男性反而微升 0.8°。

图 1 · 峰值出现在着陆周期的什么阶段？

四组对照（男/女 × 疲劳前/后）。红色虚线 = 40° ACL 风险阈值。各组模式一致：VGRF 最早出现（约 45–53°），膝外翻最晚（>80°）。数据为原图 2–5 的近似读数。

图 2 · 疲劳如何改变 VGRF 峰值时的膝屈角？

性别 × 疲劳交互 p<0.05；误差棒 = ±1 SD。女性 52.7°→47.1°（−5.6°），男性 48.8°→49.6°（+0.8°）。交叉形态即交互作用。

图 3 · 疲劳如何改变外侧腘绳肌峰值激活时的膝屈角？

交互 p=0.003。男性 62.2°→73.7°（+11.5°），女性 77.8°→75.0°（−2.8°）。峰值位于膝屈 >60° 的着陆后期，作者认为其 ACL 临床相关性有限。

图 4 · 六个变量峰值与 40° 风险阈值的相对位置？

全部峰值落在红色高风险区（<40°，着陆初期）之外；VGRF 最接近风险区（≈49°）。为四组近似均值。
